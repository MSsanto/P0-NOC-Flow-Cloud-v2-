# Retrospectives — P0 NOC Flow Cloud v2

Este documento mantém o histórico consolidado das Sprint Retrospectives. O objetivo é registrar aprendizado e ações concretas de melhoria, sem transformar retrospectiva em relatório de desempenho individual.

## Como registrar

Para cada Sprint, documentar:

1. o que funcionou bem;
2. o que gerou fricção ou risco;
3. o que aprendemos;
4. quais ações de melhoria serão executadas;
5. responsável e prazo/target Sprint de cada ação.

Ações abertas devem ser revisadas na retrospectiva seguinte.

## Princípios

- foco no processo, não em culpabilização;
- ações devem ser específicas e verificáveis;
- problemas recorrentes devem gerar mudança concreta de processo, documentação ou automação;
- impedimentos técnicos relevantes devem ser encaminhados ao especialista responsável;
- riscos de segurança ou qualidade não devem ser reclassificados apenas para preservar velocidade da Sprint.
