# Homologação manual — v0.4.0-beta

## Objetivo

Este roteiro contém **somente verificações que exigem julgamento humano**. Persistência, migrations, contratos HTTP, RBAC, tenant scoping, snapshot imutável, regressão de incidentes, builds, audits e smokes já são cobertos pelos gates automatizados.

A homologação não autoriza produção pública; a candidata é para ambiente local ou demo privada protegida.

## Pré-condição

Use a `main` após o merge da Sprint 4 e dados exclusivamente sintéticos.

A interface pode ser validada localmente com:

```powershell
docker compose down -v
docker compose up -d --build
```

ou na demo privada protegida, quando disponível.

## 1. Dashboard — leitura operacional

Abra `/dashboard`.

Confirme visualmente:

- os três indicadores são compreensíveis sem explicação externa;
- a fila ativa é fácil de escanear;
- severidade/status não dependem somente de cor;
- links para incidentes são evidentes;
- não existe clipping/overflow em notebook e aproximadamente 1024 px;
- loading/empty/error não deslocam a interface de forma confusa.

**Aprovar se:** em poucos segundos for possível identificar se há incidente ativo/crítico e abrir o incidente correto.

## 2. Passagem de turno — fluxo humano

Abra `/handovers`.

Com pelo menos um incidente sintético ativo, confirme:

- preview explica claramente o que será transferido;
- observações gerais são fáceis de localizar;
- “Finalizar passagem” deixa claro que a operação é imutável;
- a confirmação não parece uma ação destrutiva ambígua;
- após finalizar, versão, responsável, horário e quantidade de itens ficam evidentes;
- histórico permite entender que versões anteriores continuam disponíveis.

Depois altere/normalize o incidente original e reabra a versão finalizada.

**Aprovar se:** visualmente fica claro que a passagem antiga continua representando o momento em que foi finalizada.

## 3. Teclado e foco

Sem mouse:

- percorra navegação principal;
- abra Dashboard;
- abra Passagem de turno;
- chegue ao campo de observações e botão de finalização;
- cancele uma confirmação;
- continue navegando.

**Aprovar se:** o foco permanece visível e nenhuma ação essencial exige mouse.

## 4. Demo privada protegida

Na URL privada do Cloudflare Access:

- abra uma janela anônima/não autenticada;
- confirme que a aplicação não fica exposta diretamente;
- autentique-se pelo Access;
- confirme que Dashboard, Incidentes e Passagem de Turno carregam normalmente.

Este é o único passo que prova a experiência real do perímetro de identidade; o CI valida configuração/build, mas não substitui uma sessão humana no provedor externo.

## Critério de decisão

**APROVADA — DEMO PRIVADA** quando os quatro blocos acima estiverem satisfatórios e não houver problema BLOCKER/MAJOR na experiência.

**APROVADA COM RESSALVAS** somente para ajuste visual/acessibilidade não bloqueante documentado.

**REPROVADA** se a interface induzir decisão operacional errada, ocultar contexto do snapshot, impedir navegação por teclado ou se a demo privada puder ser acessada sem o controle esperado.

## Fora deste roteiro

Não é necessário repetir manualmente:

- migrations;
- CRUD técnico por Swagger;
- 401/403 automatizados;
- cross-tenant automatizado;
- payload forjado;
- versionamento de handover;
- imutabilidade de snapshot;
- regressão Sprint 2;
- lint/type-check/unit/integration/build/audits/smokes.

Esses pontos já possuem evidência automatizada da Sprint 4.
